## Known gaps

- Compose is a callback button that replies with the draft, not a one-tap URL button. Telegram inline URL buttons accept only HTTP(S) and `tg://`, so a `mailto:` button is rejected. One-tap Compose on the phone would need a small HTTPS redirect page, which the `BOT_PUBLIC_URL` placeholder in `.env.op.example` would serve. Not built.
- The bot has not been run against Telegram; the sandbox has no token. `parse_mode` HTML, 429 handling and message edits are untested live.
- Filter routing, for row 2 and for Skip-reason tuning: an `apply` signal carries the company's permanent postings too (Red Badger: 4 contract of 14); the digest lists contract postings first, tagged with their `route_reason`. Concord "Principal Software Engineer" ($75–85/hr W-2) stays `outreach` because no contract phrase matches; "Project Manager – AI-enabled Software Delivery" and "Business Process Architect" pass the engineering check on "software"/"architect"; "QA Lead Cypress", "Data Modeler", "Technical Consultant" and Domaine "Mirakl Dropship Configuration Lead (Contract)" drop as non-engineering. Personio's `raw.employment_type` is not used yet.
- Location rule, unread countries on 2026-11-04: only postings with no location at all came out with a null `work_country`, and all are kept as `unknown`: Incentro "Low-code Developer (IT-omscholingstraject)" (hybrid from the body), "Process Automation Engineer", "Senior Data Architect"; Incentro "Supp.orter" and Ziffity "Account Executive of Sales Ecommerce for US" (both dropped as non-engineering anyway). Every location string in the DB that names a place resolves. "Westport" (Zaelab) is not in the city table; it resolves to US only because the posting is flagged remote. Also not done: a `Century City` city entry (it only appears in a Red Badger title, never in a location), `workplace_type` "onsite" values (Ashby, Lever) and BambooHR's numeric `location_type`, which would mark postings on-site and drop them; only recruitee's `on_site: true` does today. Body `hybrid` skips "hybrid cloud", "hybride cloud…" and "hybrid search"; other non-work uses of the word would tag a posting hybrid, which does not drop it.
- Naming: `companies.phases` and the YAML `phases: [p1, p2]` predate the additive frame. They are tags for which stream a seed serves, not gates; PLAN.md now says Stream 1 / Stream 2. Rename when something else touches the loader.
- Seed coverage: 39 of 119 seeds are polled (breakdown in row 3). 80 are not, mostly in-house job pages or plain forms; reasons in row 3. No seed uses Lever, SmartRecruiters or Ashby.
- US coverage: 16 of the 59 US agencies are polled (3 Greenhouse, 3 JazzHR, 4 Rippling, 2 BambooHR, 2 Breezy, 1 Workable, 1 Zoho). Not covered: First Pier (GoHire, empty board, no adapter).
- Avatria and Red Van Workshop were set to `unknown` on 2026-11-04 because their JazzHR boards are dead (`avatria` serves "Inactive Career Page", `redvanworkshop` redirects to jazzhr.com). The resolver still finds the dead Avatria board on its careers page; re-research where both hire now. Object Edge's Breezy and digital dna's Recruitee boards are live but have no openings.
- SmartRecruiters fetches one detail per listed posting on every run, because the list has no body. A large tenant would be slow at 1 req/s per host: Bosch's 4,993 postings would take over 80 minutes. No seed uses SmartRecruiters yet; check the count before adding a big one.

If such a board also drops the block, the company fails every run instead of marking its postings gone. Check this the first time a JazzHR seed empties. JazzHR, BambooHR and Rippling also fetch one page per posting, and one failed page fails that company's whole run.
