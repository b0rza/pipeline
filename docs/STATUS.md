## Known gaps

- Compose is a callback button that replies with the draft, not a one-tap URL button. Telegram inline URL buttons accept only HTTP(S) and `tg://`, so a `mailto:` button is rejected. One-tap Compose on the phone would need a small HTTPS redirect page, which would need a `BOT_PUBLIC_URL` setting. Not built.
- Telegram live, 2026-11-05: `sendMessage` with `parse_mode` HTML, flags and inline buttons works (17 messages at one per second). Button callbacks and message edits confirmed live the same day for Applied, Skip and Snooze. Still untested live: the Compose reply and 429 handling. There is no undo for a press in Telegram: the overview page has Reopen (back to `new`, so the signal is re-sent), but nothing restores a pressed message to `notified` with its buttons; on 2026-11-05 that was done by hand. `notify` cannot reach Telegram from the agent sandbox (grammy does not use the sandbox proxy), so a live send from an agent session needs the sandbox off.
- Gone postings, done 2026-11-05: pending views (digest, page Pending, out files) list only postings still on the board; a pending signal with none left is marked `skipped` / `gone` by `expireGone()` before `supersede()`; sent messages and History show a gone posting struck through with "gone". Open: an `apply` signal whose contract postings are all gone still shows as APPLY with its permanent ones (re-routing needs a decision on which list History shows); Reopen on a `gone` signal does not bring it back; the Telegram messages sent before the change update only when a button is pressed.
- Remote scope phrases were derived from 67 remote postings of about 20 companies, all the restricted ones in the US. Expect misses and false hits on other countries and languages (German, Dutch and Nordic bodies have no phrases yet) now that row 5 added 81 seeds, 45 of them outside the US; `tests/location.test.ts` holds the guard sentences. The scope is only in `route_reason`, not its own column, and `work_country` is not moved to match it.
- `npm run filter` re-tags only postings with an event on `RUN_DATE`. After a rule change, re-run it per run date in the DB (`for d in ...; do RUN_DATE=$d npm run -s filter; done`); on a past date it can also add or delete that date `new` signals.
- Filter routing, for row 2 and for Skip-reason tuning: an `apply` signal carries the company's permanent postings too (Red Badger: 4 contract of 14); the digest lists contract postings first, tagged with their `route_reason`. Concord "Principal Software Engineer" ($75–85/hr W-2) stays `outreach` because no contract phrase matches; "Project Manager – AI-enabled Software Delivery" and "Business Process Architect" pass the engineering check on "software"/"architect"; "QA Lead Cypress", "Data Modeler", "Technical Consultant" and Domaine "Mirakl Dropship Configuration Lead (Contract)" drop as non-engineering. Personio's `raw.employment_type` is not used yet.

Every location string in the DB that names a place resolves. "Westport" (Zaelab) is not in the city table; it resolves to US only because the posting is flagged remote. Body `hybrid` skips "hybrid cloud", "hybride cloud…" and "hybrid search"; other non-work uses of the word would tag a posting hybrid, which does not drop it.
